# 사무자동화산업기사 실기 시뮬레이터

공개 주소: https://sumilee-phd.github.io/OA-sim/ · 저장소: https://github.com/sumilee-phd/OA-sim (2026-11-11 공개)

『2027 사무자동화산업기사 2권 실기』 10~16장 과제를 Office 없이 연습하는 웹 시뮬레이터입니다. Excel·Access·PowerPoint의 시험 장면(리본 위치, 대화상자, 인쇄 미리 보기)을 재현하고, 작업 결과를 책의 실측값으로 자동 채점합니다. 빌드 과정이 없는 정적 파일(HTML·CSS·JS)입니다.

작성: 2026-11-11. 구현 기준과 완료 점검표는 [장면목록.md](장면목록.md)입니다.

## 만든 원칙

- 탭·그룹·단추 이름과 배치는 Office 2021 한국어판 기준입니다. Microsoft 아이콘·그림·로고는 복제하지 않았습니다. 아이콘은 직접 그린 단순 도형(SVG)이나 글자입니다.
- 받는 단축키는 2권 표 9-4의 키뿐입니다. 표에 없는 동작은 리본 단추나 오른쪽 단추 메뉴로 합니다.
- 시험 과제에 쓰지 않는 기능은 단추를 비활성으로 두고, 단추 위에 「이 시뮬레이터에서 다루지 않는 기능」을 표시합니다.
- 채점 기대값은 책 원고의 검산 상자와 실측 JSON(`90_자산/그림/ch10~ch14/verify_results.json`, `ch15/verify_ch15_p2.json`, `ch16/mock1~4_results.json`)에서 가져옵니다. 화면 엔진의 계산값은 같은 값과 대조해 0건 불일치를 확인했습니다(아래 「시험」).
- 책 원고 md, 조판 파일, `90_자산/cbt/`는 고치지 않았습니다.

## 과제 구성

| 홈 화면 카드 | 내용 | 시작 방법 |
|---|---|---|
| 장비 점검 세트 | 10~14장 과제, 출력물 5매(5-1 작업표·그래프, 5-2 피벗, 5-3 조회화면, 5-4 보고서, 5-5 슬라이드) | 처음부터(시험처럼)·실습 파일로 시작·이어서 하기, 장별 연습(10~14장 각각) |
| 15장 유형 과제 | 과제 A~F 수식 연습, 출력물 없음 | 과제 시작·실습 파일로 시작 |
| 모의 1~4세트 | 16장 모의평가(사내 교육 수강, 차량 운행, 도서 대출, 행사 참가), 2시간, 출력물 5매 | 처음부터(시험처럼)·실습 파일로 시작 |

- 처음부터: 빈 통합 문서, Access 새 데이터베이스 화면, PowerPoint 시작 화면에서 출발합니다.
- 실습 파일로 시작: 책의 시작 파일과 같은 상태(원자료가 입력된 시트, 빈 데이터베이스, 4:3 빈 슬라이드 2장)에서 출발합니다.
- 장별 연습의 11장은 10장 완성, 13장은 12장 완성 상태에서 출발합니다(책의 시작 파일과 같음).

## 화면 구성

- 위쪽 띠: 홈, 과제 이름, 지시문 창 열기·닫기, 경과 시간(모의 2시간), 「출력물 5매 미리 보기·채점」, 단축키 표, 과제 초기화
- 왼쪽 과제 창: 지시문(자료·작성 조건 표, 슬라이드 원안 그림), 작업 순서, 따라 하기(원고 단계), 시작 상태
- 가운데: 프로그램 창. 아래 작업 표시줄로 Excel·Access·PowerPoint를 바꿉니다. 저장하지 않은 파일은 표시줄에 점으로 표시합니다.
- 채점 화면: 편철 순서(5-1 → 5-5)의 A4 미리 보기와 자필 기입 위치, 부록 표 A-1 점검 항목별 결과·근거 절·안내, 책의 실측 출력 견본

진행 상태는 브라우저 `localStorage`(키 `oa-sim-v1:session:<세트>[:장]`)에 저장합니다. 기기·브라우저마다 따로 저장되며 서버로 보내지 않습니다. 홈 화면 맨 아래 「진행 상태 모두 지우기」나 과제의 「초기화」로 지웁니다.

## 실행 방법

### 바로 열기

`index.html`을 더블클릭합니다. 앱은 외부 요청을 하지 않습니다(과제 자료는 `data/scenarios.js`, SQL 엔진의 WebAssembly는 `vendor/sql.js/sql-wasm-b64.js`의 base64를 읽음). 이번 점검은 아래 로컬 서버에서 했고, `file://`로 연 화면은 따로 확인하지 않았습니다.

### 로컬 서버로 열기

GitHub Pages와 같은 조건(`http://`)으로 확인하려면 이 폴더에서 다음을 실행한 뒤 `http://127.0.0.1:8773/`을 엽니다.

```powershell
python -m http.server 8773 --bind 127.0.0.1
```

ICT폴리텍 저장소의 `.claude/launch.json`에 같은 설정(`oa-sim`)이 있어 Claude Code 미리보기로도 띄울 수 있습니다.

권장 화면은 PC 브라우저, 가로 1000px 이상입니다(그보다 좁으면 안내 띠가 나옵니다).

### 웹 브라우저가 먼저 가져가는 키

표 9-4의 키 가운데 다음은 브라우저가 먼저 처리할 수 있어 같은 동작을 다른 경로로 열어 둡니다. 단축키 표 화면에도 같은 안내가 있습니다.

| 키 | 브라우저 동작 | 시뮬레이터의 대체 경로 |
|---|---|---|
| Ctrl+1 | 첫 번째 탭으로 이동 | 오른쪽 단추 > 셀 서식, 홈 탭 표시 형식 그룹의 대화상자 표시 단추 |
| Ctrl+Page Down·Ctrl+Page Up | 브라우저 탭 전환 | 시트 탭 누르기 |
| F11 | 전체 화면 | 탐색 창의 « 단추 |

## 라이선스 판단

- 수식 엔진: 외부 스프레드시트 엔진(HyperFormula 등)은 라이선스 조건(GPL 또는 상용) 때문에 쓰지 않고 직접 구현했습니다. 지원 함수는 2권 10~16장 과제에서 쓰는 함수를 포함한 약 70개입니다(`js/excel/formula.js`의 `FN`).
- SQL 엔진: sql.js(MIT). 라이선스 전문은 `vendor/sql.js/LICENSE`에 함께 둡니다. Access 문법(IIf·Nz·큰따옴표 문자열·& 연결·Like *·같은 SELECT의 별칭 참조 등)은 `sqlx.js`가 SQLite 문법으로 바꿔 실행합니다.
- 그 밖의 라이브러리는 쓰지 않았습니다.

## 시험

### 정답 JSON 대조(Node)

```powershell
node test/verify.js           # 전체 세트
node test/verify.js mock2     # 세트 하나
```

엔진 파일을 Node에서 불러와 모범 풀이를 화면 엔진으로 계산한 뒤 실측값과 대조합니다. 하나라도 어긋나면 종료 코드 1입니다.

- Excel: 10장 수식 결과·집계·정렬 순서·표시 형식, 11장 피벗 그룹 합계·총합계·위치(`ch10`·`ch11` `verify_results.json`), 15장 과제 A~F(`verify_ch15_p2.json`), 모의 1~4세트 작업표·피벗(`mockN_results.json`)
- Access: 12.4절 SQL 두 표기의 일치와 실행 결과, 변형 연습 정답, 13장 그룹 합·총평균·쪽 수·서식 전후 값, 10% 구문 오류 메시지와 매개 변수 입력 창
- PowerPoint: 도형 수·종류·순서, 유인물 틀 실측 위치(±0.05cm)
- 채점기: 모범 풀이는 모든 항목 통과, 오답 사례(정렬 누락, 보조 축, 조건 분리, 서식 누락, 도형 누락, 글머리 기호 누락 등)는 해당 항목만 실패. ❖를 글자로 입력한 경우는 통과(14.3 「기호를 글자로 직접 입력해도 인쇄 결과는 같다」)

2026-11-11 실행 결과: 대조 211건, 일치 211건, 불일치 0건, 데이터 version `1d6a2680288a`.

화면 조작 도우미 사용법(개발자 도구 콘솔 또는 자동화 도구):

```js
eval(await (await fetch('test/ui_driver.js')).text());   // window.__T
eval(await (await fetch('test/ppt_replay.js')).text());  // __T.ppt
await __T.ppt.slide(0); await __T.ppt.slide(1);           // 14장 원안을 화면 조작으로 다시 그리기
await __T.ppt.slide(0, 'mock3');                          // 모의 3세트 제1 슬라이드
```

## 과제 자료 다시 만들기

원고를 고친 뒤 이 폴더에서 실행합니다.

```powershell
python tools/build_data.py            # data/scenarios.json·scenarios.js 생성, 슬라이드 그림 복사
python tools/build_data.py --check    # 다시 만들지 않고 기존 파일과 비교(같으면 「같음 <version>」)
```

스크립트는 2권 원고(`20_원고/2권/ch09~ch16.md`, `a1_점검표.md`), 실측 JSON, `90_자산/그림/ch14/verify_ch14_ppt.py`·`ch16/build_mock.py`의 슬라이드 정의를 읽기만 합니다. 원고 표 10-1·12-1·12-2·16장 표와 실측 자료를 대조해 어긋나면 파일을 쓰지 않습니다. 출력에 시각 정보를 넣지 않으므로 같은 원고에서 같은 파일이 나옵니다.

## 단순화한 부분

- 범위에서 뺀 기능은 [장면목록.md](장면목록.md) 끝 「범위에서 뺀 것」에 있습니다.
- 글자 폭은 브라우저 글꼴로 근사합니다. 도형 안 글자의 줄 바꿈 위치가 Office와 다를 수 있습니다(예: 2.7cm 상자 안 13pt 다섯 글자). 원안 슬라이드는 텍스트 여백 0.1cm로 실측했지만 시뮬레이터의 새 도형 여백은 PowerPoint 기본값(좌우 0.25cm)입니다. 줄이 나뉘면 14.3-5대로 도형 서식 > 크기 및 속성의 여백을 줄입니다.
- 채점은 결과(값·서식·속성·도형 수와 종류)를 봅니다. 조작 순서와 도형 위치 좌표는 보지 않습니다. 자필 기입·편철은 「직접 확인」으로 표시합니다.
- 차트는 묶은 세로 막대형·꺾은선형·표식이 있는 꺾은선형과 그 혼합만 그립니다.
- Access 쿼리는 선택 쿼리만 실행합니다(실행 쿼리 단추는 비활성).

## 원고 확인 요청(시뮬레이터 점검 중 발견)

책 원고는 고치지 않았습니다. 저자 확인이 필요한 곳입니다.

1. 10.2 따라 하기 9 「I5:K18과 K22를 선택」: B18:J18이 병합되어 있어 마우스로 I5에서 K18까지 끌면 Excel이 선택을 병합 범위까지 넓혀 B5:K18이 됩니다. 그대로 ₩ 형식을 넣으면 D~G 열(G 열 백분율 포함)이 바뀝니다. 실측 스크립트는 COM으로 I5:K18만 지정해 이 문제가 드러나지 않았습니다. 「I5:K17을 선택한 뒤 Ctrl을 누른 채 K18·K22를 선택」 같은 표현을 검토합니다.
2. 10.1·10.2 따라 하기에 H5:H16(설치위치, 문자) 가운데 맞춤 단계가 없습니다. 작성 조건 「문자 셀은 가운데 맞춤」과 실측 스크립트(`verify_ch10_excel.py` 209행)는 가운데 맞춤입니다.
3. 14.3 따라 하기 6의 마름모 글머리 기호 위치 「둘째 줄 셋째 칸」: 그림 14-13 캡처에서는 ❖가 둘째 줄 둘째 칸, ➢가 둘째 줄 셋째 칸입니다. 시뮬레이터의 글머리 기호 대화상자는 캡처 배치를 따랐습니다.
4. 14.2 따라 하기 11은 점선 묶음 상자를 「도형 채우기 없음」으로 바꾸라고 하는데, 실측 슬라이드 정의(`verify_ch14_ppt.py`)는 흰색 채우기입니다. 채점에는 영향이 없습니다.

## GitHub Pages 배포 절차

저장소는 만들지 않았고 배포하지 않았습니다. 공개 여부와 저장소 이름을 정한 뒤 다음 순서로 진행합니다.

1. 공개 시점을 정합니다. 배포하면 책 출간 전이라도 과제 지시문·자료·모범 결과(채점 기준)가 공개됩니다.
2. 푸시 계정을 확인합니다. 다른 공개 사이트(NA2-com, ICE-study, pidocs)와 같은 `sumilee-phd` 계정을 씁니다.

   ```powershell
   gh auth switch --user sumilee-phd
   ```

3. 이 폴더만 새 저장소로 만듭니다. `<저장소이름>`과 `--public`/`--private`는 결정에 맞게 바꿉니다. GitHub Pages는 무료 계정에서 공개 저장소만 지원합니다. Jekyll 처리를 건너뛰도록 빈 `.nojekyll` 파일을 함께 올립니다.

   ```powershell
   cd "U:\2026\전자책출간관련\13_사무자동화산업기사\90_자산\실기시뮬레이터"
   New-Item -ItemType File .nojekyll
   git init -b main
   git add .
   git commit -m "사무자동화산업기사 실기 시뮬레이터"
   gh repo create sumilee-phd/<저장소이름> --public --source . --push
   ```

4. GitHub 저장소의 Settings → Pages에서 Source를 「Deploy from a branch」, Branch를 `main` / `/ (root)`로 저장합니다. 명령으로 하려면 다음을 실행합니다.

   ```powershell
   gh api -X POST repos/sumilee-phd/<저장소이름>/pages -f "source[branch]=main" -f "source[path]=/"
   ```

5. 1~2분 뒤 `https://sumilee-phd.github.io/<저장소이름>/`에서 홈 화면, 장비 점검 세트의 처음부터 시작, 세 프로그램 전환, 채점 화면, 새로고침 뒤 이어서 하기를 확인합니다.

이후 원고를 고치면 `python tools/build_data.py`로 `data/`를 다시 만들고 `node test/verify.js`가 0건 불일치인지 본 뒤 커밋·푸시합니다. 저장소에는 `tools/`·`test/`가 들어가지만 원고 폴더는 들어가지 않으므로 자료 재생성과 대조 시험은 이 작업장에서 합니다.
